# MathInk AI 开发计划

版本：第一版。更新：2026-10-24。

采用 DeepSeek 云端作为主要开发路线，保留 Qwen 本地可选模式。两种模式共用笔记、编辑器、来源定位和建议确认流程；近期的新能力优先在云端完成验收，再按实际需求扩大本地支持范围。

首个目标版本支持：整页中英文字与数学公式转为可编辑排版草稿，结合本段或本页上下文提出修改建议，经用户确认后整理成笔记。知识关联和证明辅助在这个基础上逐步加入。

## 产品范围与模式分工

| 功能 | DeepSeek 云端主线 | Qwen 本地可选模式 |
| --- | --- | --- |
| 手写、保存、编辑、搜索、备份、导出 | 在用户设备完成 | 共用相同本地功能 |
| 选区公式转写与检查 | 先完成真实质量评测 | 保留当前实验能力及限制提示 |
| 整页中英混排与上下文纠错 | 近期核心交付 | 通过专项评测后逐项开放 |
| 笔记整理与知识关联建议 | 在用户选定内容范围内生成 | 随阶段 4 提供本地全文搜索和人工关联 |
| 证明步骤辅助 | 后续限定领域试验 | 暂不承诺小模型支持 |

默认推荐 DeepSeek；已选择本地的用户继续使用本地设置。Qwen 失败、超时或不支持某项任务时，说明原因并提供手工处理入口；只有用户明确选择云端后才上传和计费。功能是否开放由任务能力表控制，不能因为两个后端兼容相似 API 就视为能力相同。

本地模式目前指电脑运行 Ollama，平板经电脑网关访问。平板独立推理单独立项。普通用户只用平板访问云端，则需要托管 MathInk 网关；仅修改模型设置无法实现。

首版 Qwen 继续使用本机或局域网入口。托管服务器不能访问用户电脑的回环 Ollama，HTTPS 页面连接电脑 HTTP 网关也受浏览器限制，因此托管版先提供本地模式的启动说明和入口，不承诺同一页面一键接入用户电脑模型。

## 当前基础与需要补齐的能力

目前已经具备选区转写、独立公式检查、DeepSeek/Qwen/Mathpix 适配、显式采用建议、原稿关联、IndexedDB 保存、备份导出，以及请求去重和按次数计算的配额。

[开发预览记录](DEVELOPMENT-PREVIEW.md)尚未记录 DeepSeek 真实质量、延迟和费用验收。本地 Qwen 的少量实测出现复杂公式误读和错误积分漏检，因此本计划不把现有接口测试当成模型质量证明。

实施前需要明确四个缺口：

- 当前数据主要是笔迹、公式数组和 Markdown，没有可编辑的页面内容块、阅读顺序及行内公式结构。
- `note.revision` 主要随原稿变化；编辑 Markdown 或已保存公式不会递增它。上下文纠错需要另外跟踪内容修订，避免旧建议被应用到新内容。
- 网关 SQLite 保存请求和额度元数据，结果正文仅在内存；它还不是可恢复的整页任务系统。现有次数额度也不是金额账本，公式检查尚未向上层保留模型用量。
- 当前托管配方仍面向单实例和配对令牌；面向多个普通用户需要账号鉴权、用户预算和使用记录。部署说明与发布清单仍有 Mathpix 默认项，应随主线调整。

## 共用架构

### 页面结构和原稿来源

在现有模型上增加以下对象，沿用现有公式 ID 和原稿字段：

| 对象 | 作用与必要内容 |
| --- | --- |
| Page | 稳定页 ID、所属笔记、原生画布页映射、原稿修订、内容块顺序 |
| Block | 稳定块 ID、类型、内容修订、段落或公式引用、待核对状态 |
| SourceRef | 笔记和页 ID、笔迹 ID、原稿修订、页内坐标、裁切或缩放变换 |
| Suggestion | 目标块、原内容快照、建议内容、原因、依据、上下文版本、采纳状态 |
| Task | 任务类型、供应商和模型、输入版本、子步骤状态、用量和错误 |

段落内容支持文字片段和行内公式引用；独立公式、多行推导使用公式块。LaTeX 以现有公式对象为唯一可编辑来源，避免在块正文和公式数组里维护两份副本。Markdown 作为导出结果及旧数据迁移输入。

保留原稿修订语义，增加内容修订和块修订。每个建议绑定目标及所引用上下文的版本快照；任何相关内容改变后，旧建议只能查看，重新检查后才能应用。原稿、转写草稿、AI 建议、已采纳内容分别保存，支持撤销并返回具体原稿位置。

升级 IndexedDB 和备份格式时，先提供可恢复备份和失败处理；新版本能导入旧格式，保留笔记、公式和来源 ID。旧客户端遇到新格式应明确提示不兼容，不能无声丢弃内容。原有思源来源属性继续复用。

不同地址的浏览器存储彼此隔离。从电脑局域网地址改用托管 HTTPS 域名，或在两个入口间使用笔记时，需要从旧入口导出完整备份，再在新入口导入并核对。数据库版本升级只处理同一来源内的数据，不会自动跨地址搬移；首版提供明确的迁移向导。

### 按任务选择模型

保留 `/v1/recognize`、`/v1/review` 的现有调用兼容性，逐步增加整页转写、上下文检查、整理和证明辅助的独立协议。新任务返回结构化内容，不能把整页所有内容塞入一个 `latex` 字段。

- 转写强调忠实识别，保留原文错误及不确定符号；识别阶段不补条件、不求值。
- 上下文检查和证明辅助使用独立提示词、输出结构、推理模式、超时及输出预算。
- 整理保留命题条件、公式与来源；新增解释和原文摘要分别标示。
- 每个适配器声明支持的任务、输入类型及限制；本地不支持的任务明确禁用。

当前官方 `deepseek-flash` 支持图像输入，可作为首轮视觉候选；官方接口也提供思考模式控制。具体模型与模式由评测确定，并允许服务端配置替换。不能把开启思考模式视为数学正确性保证。[视觉文档](https://api-docs.deepseek.com/guides/vision/) · [思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)

先沿用现有 Web、Node 网关和 SQLite。新增职责按页面模型、任务路由、上下文组装、建议应用拆开，避免继续集中到 `main.ts`。初期不引入多智能体系统或专门图数据库。

## 分阶段交付

### 阶段 0 验证云端和建立评测基线

目标：确认 DeepSeek 能在实际笔记上改善整理体验，并测出费用和响应时间。

- 在开发者本地安全配置凭据，预先设置试验预算；从少量真实调用开始，分别验证图像转写和文字检查。
- 先整理 30–50 页真实样本，覆盖中文、英文、中英混排、公式密集页、带涂改的笔记。优先凑齐 50 页，按书写者或笔记来源划分 30 页调试、20 页验收，避免同一内容跨组。
- 另外准备至少 40 道检查题，正确和错误各半，覆盖积分、不等式、条件遗漏、矩阵和多行推导；期望结果由人工核对。
- 建立可重复运行的评测脚本，保存模型配置、提示词版本、输入样本标识、输出、人工修改量、延迟和用量。私人样本留在本机或明确授权的测试存储中，不进入发布包。
- 分开记录中文字符错误率、英文词错误率、阅读顺序和公式整式正确率。公式先规范化无关格式，再由人工核对数学含义、上下标、条件和漏行，不能只比较 LaTeX 字符是否完全相等。模型或提示词升级后复跑冻结集。
- 补齐各任务用量传递，区分输入、输出及供应商提供的其他计费字段。费用按带日期的价格配置估算，再与供应商账单核对；缺少数据时显示未知。

完成标准：有真实云端报告、失败样本分类、拟支持页面范围，以及单页延迟和费用预算。连接探测成功不能代替生成验收。若视觉效果不够，先比较分块输入和现有 Mathpix 对照；确有缺口再评估专用识别器，其他功能仍沿用共同流程。

### 阶段 1 页面模型与数据迁移

目标：在不丢失现有笔记的前提下，为整页编辑建立基础。

- 落实 Page、Block、SourceRef 与内容修订，增加纯文字段落、行内公式、独立公式和多行推导。
- 实现旧笔记迁移、备份版本升级、导入导出和来源跳转；旧 Markdown 先作为兼容块保留，不能靠未经确认的 AI 重写迁移。
- 抽出通用建议预览与采纳逻辑，保留现有公式检查的取消、快照校验和显式采用行为。

完成标准：旧格式导入、新格式保存重开、导出再导入后内容与来源一致；修改文字、公式或上下文会使相关旧建议失效；撤销采纳可恢复原内容。此阶段可以在等待云端评测时推进。

### 阶段 2 当前单页转为排版草稿

目标：用户点一次整页整理，就能得到可对照、可编辑的中英数学排版草稿。

- 提供当前页完整渲染和坐标映射，扩展 Butterfly 桥接，不以当前屏幕截图代替完整页面。
- 先支持较清晰的单栏页面，保留标题、段落、列表、行内公式和公式行。复杂多栏、图表、图形证明保留原图区域并提示手工处理。
- 按页面实际清晰度分块或裁切，显式记录阅读顺序；允许人工拆分、合并、重排和纠正类型。先做好块级编辑，不追求与手稿像素位置完全一致。
- 显示原稿和草稿对照、未完成块及不确定内容；每块可以返回原稿。新增整页上传范围说明，不能沿用仅上传选区的旧提示。
- 将任务进度和已收到的草稿保存到设备。每个子请求复用网关去重和额度；部分失败后允许继续未完成部分，重做失败部分需用户确认。已提交但结果未知的请求不得自动重复生成。
- 网关重启后若结果已丢失，显示状态与可能再次计费的重做入口。未来跨设备恢复若需要服务端保存正文，应先定义保存期限、删除规则并更新隐私说明。

完成标准：真实页面可完成“整页输入—逐块核对—编辑—保存—离线重开—导出”；失败或取消不破坏原稿和已保存草稿。页面级等待时间、费用和质量达到后述验收目标。

### 阶段 3 上下文纠错和笔记整理

目标：把单页草稿变成有帮助的笔记整理工具，形成首个核心试用版本。

- 上下文从用户选择的本段或本页开始；清楚展示本次发送范围。跨笔记内容留到阶段 4。
- 将建议分成识别疑点、语言表达、数学问题和缺少条件；显示改前、改后、理由及所依赖的块。区分“原稿可能写错”和“识别可能看错”。
- 对条件不足的结论保留疑问，不自动补出假设后当作原文。模型输出通过结构校验和受限渲染后再展示。
- 整理提供标题、层次、摘要及定义/定理/例题归类建议；默认形成新草稿，采纳后才更新已整理笔记。原有公式、条件和来源不得被摘要替代。
- 保留逐条采纳、拒绝、撤销；只对用户勾选且版本仍有效的建议提供批量采纳。

完成标准：选定范围可纠错、整理并追溯到原稿；不存在过期建议覆盖、新增假设冒充原文、取消后仍修改笔记等流程错误。人工整理时间和误改指标达到本计划的核心试用门槛。

### 阶段 4 有来源的知识关联

目标：帮助用户找回相关知识，并建立能解释原因的笔记联系。

- 先扩展本地全文检索，覆盖正文、公式和标签；支持人工链接、反向链接及稳定的内容块跳转。
- 只在用户选定的笔记范围内检索，将有限的相关块交给云端生成关联建议，展示引用原文和关系理由。
- 关系先采用少量可理解类型：定义、使用的定理、例子、反例、推导依赖。没有依据时允许不生成关系。
- 为内容修改和删除处理索引失效、来源过期及断链。来自笔记的文字作为资料，不得改变任务权限或上传范围。
- 只有全文检索的漏召回影响实际使用时，再评估向量检索及重排；单独选择对应模型，不假定 DeepSeek 对话接口提供嵌入能力。

完成标准：推荐关系可跳回准确来源，编辑和删除后不继续引用过期内容；在预先标注的查询集上统计前五条结果命中情况和无依据关系数量。先验收检索与链接，再考虑知识图谱可视化。

### 阶段 5 限定范围的证明辅助

目标：帮助用户推进推导，同时清楚区分生成建议与验证结果。

- 先支持初等代数和基础微积分中的步骤提示、缺失条件检查、定理引用和反例建议；输出目标、假设、已有步骤、建议下一步和待解决问题。
- 复用来源块、检索和建议机制，按步请求和采纳；遇到缺少定义或无法完成的推导时说明未解决部分。
- 为可计算任务接入受控的符号计算或数值检查，展示工具、条件和验证范围；数值样例通过不能标为普遍证明。
- 后续选少量适合形式化的命题接入 Lean 等证明检查工具，并检查形式化陈述是否对应原意、依赖假设是否合适。模型生成完整文本仍显示为建议，工具验证结果单独记录。

完成标准：独立的正确题、错误题和缺少条件题集均有逐步评审；不会把未验证补全显示为已证明。形式验证作为单独里程碑，不影响整页整理版本交付。

## 核心试用版本的验收标准

以下为拟定工程目标，不是当前已达到的指标。阶段 0 后冻结样本、任务定义和性能预算。达不到时优先缩小支持范围或改进处理流程，并记录原因，不能用调试集的最好结果替代验收。

| 项目 | 衡量方法与试用门槛 |
| --- | --- |
| 内容保留 | 人工标注段落、公式和关键条件等内容单元；在支持范围内的验收页上，各类正确保留单元占比目标至少 95%，另列漏段和条件遗漏，避免大量普通文字掩盖公式错误 |
| 人工修改时间 | 同一批页面比较全手工整理与 AI 后核对修改，交错安排顺序；总时间中位数目标减少至少 30%，保留每页数据 |
| 数学检查 | 正确题统计错误修改建议，目标不超过 5%；错误题统计正确指出问题的比例，目标至少 80%；分别报告分子分母和题型 |
| 延迟 | 记录整页可用草稿完成时间、检查完成时间的 P50/P95，以及超时率；冷启动、输入大小、网络和设备分开记录，阶段 0 后确定预算 |
| 成本 | 记录每页和每次检查的估算费用、实际可核对账单、失败与重做费用；单任务和服务总预算均生效 |
| 数据可靠性 | 迁移、备份恢复、离线重开、取消、部分失败、重复点击、建议过期、撤销等约定用例全部通过，无原稿丢失或无确认覆盖 |
| 来源与模式 | 已保存块能定位原稿，或明确标为没有原稿关联的手工及导入内容；本地模式验证无云端请求，模式切换不继承不适用的上传授权 |

初始题集用于发现问题和决定能否邀请试用，不足以证明对所有笔迹达到相同准确率。扩大公开发布前，按现有发布方向扩充到约 300 个来自不同书写者的公式样本，并增加独立整页样本；按页面类型报告结果。

## 平板使用与云端发布

托管服务准备可以与阶段 1–3 并行，但发布以功能和服务两类验收都通过为前提。

首轮内部测试继续使用开发者自己的云端凭据和预算。面向普通用户的默认方案是：用户登录 MathInk，使用运营者提供的额度，DeepSeek 凭据只放服务器；用户无需安装 Ollama 或填写供应商密钥。调用费用由运营者承担，订阅或额度定价等取得真实成本数据后再决定。高级自带密钥模式后续另做，不阻塞主线。

需要交付：

- 可从平板直接访问的 HTTPS 网关和应用入口。当前 Docker 镜像只包含网关，需要另外部署前端静态资源并配置来源访问；先完成浏览器试用，原生安装包、商店发布和手写笔验收继续按独立发布流程执行。
- 每个用户独立身份、可撤销会话和额度。`installationId` 不能作为可信账号，共享配对令牌不能作为公开客户端长期凭据。
- 每用户和全服务的并发、频率、日/月次数及费用保护。整个页面任务限制图像大小、上下文、输出、子调用次数和总执行时间，统一预留保守预算并在结束后结算；达到预算时停止后续生成。超时、取消及供应商未返回用量的请求标记未知，不能直接视为免费。定期对账。
- 通过账号隔离、额度绕过、重复请求、服务重启、元数据备份恢复和告警演练；预算触发后不能再发起新的云调用。
- 供应商密钥不进入网页、客户端包、错误日志或备份。默认不保存服务端笔记正文；日志仅包含排障和计费必要元数据。新的整页与上下文发送范围同步更新隐私说明。
- 先小范围邀请试用并设置总预算；服务不可用或超额时，用户仍可书写、编辑、保存和导出。换用 Qwen 由用户主动打开本机或局域网入口，并按需要导入笔记备份。
- 更新部署默认示例、主线模型验收项和用户指南。Mathpix 作为可选对照，不能成为 DeepSeek 主线发布的必选凭据。原有许可、真机、备份和签名等发布要求继续保留。

跨设备笔记同步不等于云端推理，本阶段仍以本地数据和备份导出为基础；需要同步时单独定义存储、冲突和删除机制。
