## BF001-01 整页识别结果保存与恢复

### 已确认的原因

用户提示为“结果已收到但未保存，页面缩略图引用不存在的快照……”，说明模型结果已经到达，错误发生在本地保存阶段。

`draft-content.ts` 中的 `shadowDocument()` 深拷贝原笔记页面，带入了 `thumbnailId`，但给草稿子文档设置了空的 `resources`。`pageDraftContent()` 生成的内容写入草稿后，仓储递归校验子文档，发现缩略图引用缺少对应资源，于是拒绝保存。即使识别页本身没有缩略图，复制进来的其他页也可能触发该问题。

已用纯内存仓储和隔离返回复现：原笔记资源完整，整页只返回普通文字也会失败；任务保留为 `running`，收到的结果进入内存 `unsaved`，与用户所见提示一致。在内存中移除子文档继承的缩略图引用后，重试本地保存可完成，未增加网络请求。

此外，保存异常分支只发通知并缓存返回结果，没有及时让列表显示“已收到，待保存”，因此仍呈现“处理中”。这应与底层引用错误一并修补。

### 修补方案

1. **修正草稿文档的构造边界。** 草稿页只继承需要的页 ID、来源映射和内容顺序，排除笔记库封面、缩略图和画布视图等界面元数据。真实快照继续由原笔记的 `resources` 和 `Draft.snapshotIds` 管理，不向草稿子文档复制资源库；当前模型禁止草稿嵌套资源库。原笔记的缩略图与资源继续保留。
2. **保留完整性校验。** 不通过关闭校验、清空原笔记快照或为缺失资源伪造占位数据来让保存通过。检查所有调用 `shadowDocument()` 的路径，包括上下文检查、整理和手工公式检查。
3. **分开生成状态与保存状态。** 模型完成后显示“结果已收到”；本地保存中、保存失败、已保存分别显示。保存失败即停止“正在识别”的进度提示，列表与详情均提供查看收到结果、重试保存和导出入口。
4. **失败时仍能看到结果。** 以保留在内存中的返回内容生成安全预览；不能要求先保存成功才能查看。结构无法解析时提供明确错误及原始结果导出。内存预览清楚标为未保存，不能提前显示成功。
5. **重试只做本地保存。** 使用原请求结果和身份重建有效草稿，合并到最新笔记状态；不重新提交模型调用、不覆盖任务期间新增的笔迹或草稿编辑。重复点击和重复回调不能生成重复草稿或多次增加内容版本。
6. **区分保存失败与显示失败。** 数据库事务成功后，界面刷新或通知异常不能再把已保存结果标为未保存；重试前核对原任务对应内容是否已经提交。

### 已有失败结果如何恢复

- 当前页面仍开着且结果在内存时，优先使用“导出收到的结果”保护结果，再进行更新。修补后优先重放原返回结果到本地保存，不要求重新识别。
- 当前导出的未保存结果是原始 Reply，不是完整笔记备份。本轮补上对应恢复入口：根据任务 ID 关联本机已有草稿和原稿快照，并验证供应商、来源版本及内容结构，不能导入到恰好打开的另一篇笔记。
- 已刷新或关闭页面时，先按原任务 ID 查询；服务仍保留结果则恢复保存。服务缓存已消失且没有导出材料时，明确说明无法恢复，是否重新识别由用户决定。
- 对确实无法写入存储的情况，保留可查看、可复制、可导出的内存结果。不能假定“保存失败状态”本身一定能写入同一个故障存储。

### 验收要求

- 有缩略图的笔记、没有缩略图的笔记，以及仅其他页有缩略图的笔记，整页结果都能保存、查看、重开和备份恢复。
- 覆盖普通文字、行内公式、独立公式和原图区域；原稿快照和原笔记缩略图保持有效，正式页面不被识别结果改写。
- 注入保存失败后，显示“已收到，待保存”，能够查看和导出；恢复存储后点击“重试保存”成功，生成请求次数保持不变。
- 切页、切笔记或继续写字期间结果到达，仍保存到原笔记，不覆盖新笔迹，不抢焦点。
- 导出的旧失败结果可以在匹配的原任务下恢复；任务不匹配时拒绝错误归档。

## BF001-02 统一常规套索与识别选区

### 已确认的现状

实验画布已有 `lasso` 类型，但常规工具栏只挂载笔、橡皮和移动。识别入口单独切入圈选状态；结束后只隐藏识别栏、切换工具，没有清空 `selectedIds`。绘制函数仍根据选中 ID 画边框，导致回到书写时残留选区。重复进入识别还可能把上次套索误记为需要恢复的工具。

实验画布当前的平移和缩放主要改变视口，未实现所选内容的整体变换。Butterfly 原生选择器已有内容移动与缩放能力，但宿主需要统一入口和状态；其识别桥接目前只提取手写笔迹，不能默默忽略混选的其他对象。宿主“全选”也需按当前引擎调用，不能始终操作实验画布。

### 统一后的操作

- 常规书写工具栏增加“套索”，与笔、橡皮、平移并列；将原“移动”命名为“平移”，明确它用于导航画布。普通圈选不上传、不调用模型。
- 圈选后显示选区边框、移动区域和等比缩放控制点。首版支持手写笔迹及已插入公式的选择和整体移动、缩放，改变内容的实际位置与尺寸；双指缩放页面继续只改变视图。
- 工具箱“识别公式”直接读取当前有效选区。没有选区时切换到同一个常规套索并提示先选择，不再维护第二套“识别专用套索”。选区快捷菜单也可以提供识别入口。
- 本轮识别输入继续限定为手写笔迹。只选已排版公式时引导编辑或复制；混选笔迹和公式等对象时明确提示调整为纯笔迹选区，不能显示整个混选范围却只上传其中一部分。
- 获取选区快照后，本次请求固定笔记、页、修订与输入内容。提交成功后清除该次选择并回到书写；之后的原稿修改不改变已提交图片。

### 选区生命周期

| 操作 | 预期行为 |
| --- | --- |
| 常规套索选中内容 | 保留选择，允许移动、缩放或调用工具 |
| 选区内拖动或控制点缩放 | 预览变换，松手提交一次内容操作，选区继续跟随内容 |
| 点击空白处或 Escape | 清空当前选择；变换进行中则先取消本次变换并恢复初始位置 |
| 切换到笔、橡皮或移动画布 | 清除选择边框、控制点、临时套索线和识别上下文栏 |
| 套索模式下双指平移或缩放视图 | 保留仍有效的对象选择，只改变视图，不修改内容 |
| 关闭识别预览但仍留在套索工具 | 回到常规选择，保留选区供继续编辑；明确选择“继续书写”则清除选区 |
| 识别任务提交成功 | 固定快照后清除本次选择并切回笔工具，结果归草稿箱 |
| 识别完成或失败 | 只更新所属草稿；不恢复旧选区，也不清除用户后来建立的新选区 |
| 内容撤销或重做 | 清除可能失效的对象选择与控制柄，避免继续操作已删除的 ID |
| 切页、换笔记、回首页、旋转或重新挂载画布 | 不把旧页选区带入新页面；同页旋转可保留仍有效的选区，不能留下错位边框 |

增加统一选择状态接口，包括笔记/页 ID、对象 ID、边界、修订和选择代次。清除选择需同时清理宿主与引擎状态；延迟回调只能处理自己那一代选择，不能误清除用户的新选择。Butterfly 已有选区时不重复设置套索工具，避免新建选择器丢掉现有选择；全选和清空需要明确的引擎能力与桥接。

### 内容变换与历史

实验画布补齐所选笔迹和公式实例的变换；Butterfly 复用原生选择器并核对缩放语义。以手势开始时的内容快照计算最终位置，避免每次移动事件重复累加变换。等比缩放同步调整笔迹坐标、笔宽及公式展示尺寸，保留笔压与 LaTeX 内容；尺寸和边界需设合理限制。本轮不增加自由拉伸、翻转或旋转。

公式尺寸必须作为正式实例属性保存并参与重开、复制、导出及备份，不能只用临时 CSS 放大。每次拖动或缩放只产生一个撤销步骤；取消手势不留下半次修改。内容变动更新对应页面修订，已有识别草稿保留历史来源并提示原稿变化。

### 验收要求

- 不使用识别工具也可套索选择、移动、等比缩放；这一流程的模型请求数为零。
- 圈选识别后继续书写，旧边框和临时线立即消失；晚到结果不清掉新的选区。
- 已有选区调用识别无需重新圈选，空选区不发送请求；混选对象有明确处理规则和正确预览。
- 多笔画及多个公式整体变换后，未选中内容保持不变；一次撤销恢复整个手势，重做再次应用。
- 两种引擎的全选、取消、切页和缩放后命中测试都通过；存储重开后内容位置、尺寸与来源状态正确。
- 选区快照只渲染选中的笔迹，不包含选框、控制点或包围框内未选中的邻近内容；手势被系统取消时，不留下半次变换。

## BF001-03 删除公式与统一撤销

### 已确认的原因

实验画布的公式“删除”按钮直接调用 `undoInsertion()`，把删除当作撤销原始插入，没有保存删除前快照，也没有新增删除命令。随后点击撤销时，历史栈仍取到原插入记录；该实例已经被标为撤销，`captureInsertion()` 不再返回快照，因此无法恢复，还可能消耗掉原历史条目。

实验画布的笔迹历史只存 `Stroke[][]`，不能覆盖公式对象。公式移动和编辑也需要纳入顺序一致的操作历史。Butterfly 使用原生 `ElementsRemoved`、`ElementsChanged` 和原生撤销，再同步宿主记录；该路径应保留原生历史职责，不能再叠加同一次宿主删除撤销。

### 修补方案

1. **把删除作为独立用户命令。** 在删除前保存该实例的公式 ID、LaTeX、位置、尺寸、层次、内容块、来源及使用记录等必要信息；执行删除后再登记命令。
2. **撤销删除恢复删除前的实例。** 恢复同一实例及其正式内容引用，保留用户删除前对公式的修改，不能从当前草稿重新插入一个新副本。
3. **按真实时间顺序撤销。** 实验画布使用有类型的历史项，覆盖笔迹、插入、删除、公式编辑、移动和缩放。画布缩放、选区清除、草稿结果到达不进入正文内容历史。
4. **保证失败和重做语义。** 撤销与重做串行执行，未执行成功不消耗历史。区分“操作执行失败”和“已执行但保存失败”：尤其原生撤销已经成功时，只重试保存，不能再次发送撤销或重做而多消费一步，也不能用旧整篇归档回滚。撤销后发生新的内容编辑则清空失效的重做分支。按钮及快捷键执行同一逻辑。
5. **同一引擎只有一套真实变更记录。** Butterfly 继续由原生历史执行一次，宿主只同步派生公式、来源和草稿使用状态；实验画布命令只恢复相关对象，不能回滚整篇旧笔记、覆盖后台收到的草稿。
6. **明确历史作用范围。** 实验画布按笔记与页面隔离，当前会话内切页再返回可撤销本页操作。Butterfly 保留当前笔记文档的原生时间线，核对跨页操作的实际撤销目标并同步界面、提示受影响页；不伪造按页历史，也不通过连续撤销跳过其他页事件。任何路径都不能影响另一篇笔记。本轮保证最终内容持久化，跨应用重启恢复完整撤销历史不作为本版承诺。

### 必须通过的操作链

- 插入公式 A → 编辑内容 → 移动/缩放 → 删除 → 撤销：恢复删除前的 A，内容、位置和尺寸一致。
- 接着重做：A 再次删除；再撤销仍恢复同一实例，没有重复对象。
- 插入 A → 插入 B → 删除 A → 撤销：只恢复 A，B 不变；下一步撤销按实际时间顺序处理 B 的插入。
- 删除 A 后新写一笔 → 连续两次撤销：先撤销笔画，再恢复 A。
- 草稿在删除后被编辑或移入回收区，撤销仍恢复删除前的独立实例；草稿自身不被撤销删除。
- 选区移动/缩放、单个公式菜单操作、宿主撤销按钮及快捷键在对应引擎中行为一致。实际验证用户可点击的删除入口，不能只测试底层桥接。
- 原生撤销已执行后注入保存失败，再点击重试保存：只保存当前结果，不多撤销一步；快速重复点击也不能重复执行同一次命令。
- 切页后分别验证实验画布的本页历史与 Butterfly 的文档时间线，明确受影响页面，其他笔记保持不变。
